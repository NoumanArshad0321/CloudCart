⚠ Important limit of Render's free tier — please read

Render's free service has an ephemeral filesystem: files written to the server's disk are temporary. When Render restarts the service or you redeploy it, your uploaded images AND the SQLite database can be lost. The deployed demo is therefore disposable — after a restart you re-add the products. The free service also sleeps after 15 minutes without visitors, so the first visit after that takes about a minute to wake up. This is normal for a free lab demo, and it is exactly why a real shop would not store images on the web server's disk — see About and docs/RENDER_STORAGE.md.

How an image is stored
  1. You upload an image on the Add Product page.
  2. The server checks the file type (JPG, JPEG, PNG, WebP) and size (max 5 MB).
  3. The image gets a unique file name (a random UUID + the original extension) and is saved in instance/uploads/ on the server's disk.
  4. Only the file name is saved in SQLite — never the image itself.
  5. When the image is displayed, the server sends it through the /uploads/<filename> route, which only accepts UUID image names.
  6. Deleting the product deletes its database row and its image file, so nothing is left behind.
What would a production setup use instead?

Object storage — for example Amazon S3, Azure Blob Storage or Cloudflare R2. Files in object storage live outside the web server, so they survive restarts and redeploys, and they can be served to any number of users. See docs/RENDER_STORAGE.md for the full comparison.
